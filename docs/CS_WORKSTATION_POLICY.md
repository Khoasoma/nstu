# Computer science workstation application policy

These files prepare a restricted AppLocker policy and inspect its deployed Group Policy state. They do not apply policy, install software, change accounts, write HKLM, start AppIdsvc, or qualify an assessment workstation. Integrated source remains INDEV. No physical Windows workstation or Linux judgehost has been qualified by this change.

Use a dedicated, recoverable Windows exam image and an individual standard-user exam account. All five collections have rules, so AppLocker default denial also affects every other standard account on the machine. SYSTEM and the local Administrators group receive explicit recovery rules in every collection. Administrator credentials must remain unavailable to students. Review domain/local group membership, inherited GPO scope and the recovery account before deployment.

## Prepare an explicit inventory

Use Windows PowerShell with the installed Microsoft AppLocker module. Select the exact NSTU agent, WebView2 executable, and every required OS executable, DLL, runtime, Vietnamese IME, input service and accessibility dependency for the calibrated image. Each approved regular file needs its full local absolute path and independently reviewed whole-file SHA256 from `Get-FileHash -LiteralPath <selected-file> -Algorithm SHA256`. Do not inventory a directory or approve files merely because they appeared in audit events. Missing dependencies block deployment; disabling input/accessibility to make the policy pass is not acceptable.

The JSON input has exactly `version` (integer 1), `dependenciesReviewed` (boolean true after inventory review), `files` and `packages` arrays. Each file has exactly `path`, `contentSha256` (64 hex characters) and `role`. The six roles are `nstu_agent`, `webview2`, `os`, `ime`, `accessibility`, `runtime`; all must be represented. `nstu_agent` must refer to `nstu-agent.exe`, and `webview2` to `msedgewebview2.exe`. The other roles can occur on files or packages. Approval is a review declaration; the generator cannot discover a complete calibrated dependency graph.

Each approved installed package has exactly `packageFullName`, `publisher`, `name`, `version` and `role`. Copy its exact installed identity from the chosen exam account's `Get-AppxPackage -User <student-sid>` output. Package versions have four numeric sections. Empty `packages` is permitted only when the reviewed image requires no student packaged apps. AppLocker supports publisher conditions for packaged apps, so the resulting rule binds the exact publisher, package name and version; package architecture/resource variants with that publisher/name/version share AppLocker's scope. Review that platform limit. Ordinary files always use platform file hash rules, with no student path or publisher fallback.

`contentSha256` pins the complete file at preparation. Microsoft AppLocker computes its own Authenticode file hash for the generated enforcement rule; it differs from whole-file SHA256 for some binaries. Review both the intake inventory and generated policy. Updates to Windows, WebView2, IME, accessibility tools or DLLs require a new inventory, policy review and physical qualification.

Create a new administrator-controlled output directory on an existing local volume through the institution's operations process. Both the approved inventory file and output directory, including their ancestors, must be controlled by SYSTEM, Administrators or Windows TrustedInstaller; ordinary users must not be able to alter their permissions or replace their ancestry. The generator checks these ACLs and rejects reparse points, wildcards, alternate data streams, unsupported file types, mismatched content hashes and output overwrites. Keep the installed scripts under operator control.

```powershell
# Preparation only; replace all arguments with reviewed existing paths/SID.
& .\packaging\prepare-cs-policy.ps1 `
  -StudentSid 'S-1-5-21-111-222-333-1001' `
  -ApprovedInventoryPath 'D:\NSTU-PolicyReview\approved-inventory.json' `
  -OutputDirectory 'D:\NSTU-PolicyReview\new-policy'
```

Success writes new `cs-applocker-policy.xml` and `cs-applocker-review.json`, then prints `CS_POLICY_PREPARED_NOT_QUALIFIED`. The review includes the full approved inventory, student SID, canonical policy digest and explicit physical blockers. No existing file is overwritten. An I/O failure may leave an incomplete preparation pair; preserve it for review and use a fresh output directory after resolving the failure. Every collection is explicitly `Enforced`: `Exe`, `Dll`, `Script`, `Msi`, `Appx`. Script/MSI/Appx collections without student approvals retain only recovery rules and therefore deny student launches in those collections.

## Operator controlled lab deployment

Perform these operations separately in a recoverable lab, after institutional authorization. This repository's scripts never perform them.

1. Confirm the installed Windows release/update level supports AppLocker enforcement and install the required AppLocker/GPMC or RSAT tools through approved operations. Microsoft currently documents enforcement on Windows 10 version 2004 and newer with KB5024351, and Windows 11, without an edition restriction; older releases have edition/deployment limitations. Verify the actual image against the current Microsoft requirements. Manage and apply GPOs with appropriate administrative rights.
2. Preserve an offline recovery path and an accessible administrator account. Review the exact XML, all dependency hashes/package identities and the two recovery rules in each of the five collections. Determine GPO scope and precedence. Do not merge broad Windows, Program Files, Everyone or user-profile allow rules into the exam image.
3. Import the reviewed XML using the AppLocker editor in a dedicated test GPO: Computer Configuration → Windows Settings → Security Settings → Application Control Policies → AppLocker. Configure DLL enforcement explicitly and Application Identity service operation through the approved GP/service operations process. A separately reviewed Audit Only lab policy may gather dependency evidence; the supplied readiness verifier rejects Audit Only.
4. Apply that GPO only to the prepared physical lab workstation, refresh it through normal GP operations, and inspect `Get-AppLockerPolicy -Effective -Xml`. Microsoft defines this result as the merge of local and applied domain policies. Account for all actual rules and precedence. CSP/MDM policy is outside this verifier's supported method; do not label a mixed CSP/GP deployment as GroupPolicy.
5. Run the chosen account as a standard user. Record allowed NSTU/WebView2 startup, every DLL load, Vietnamese IME composition and deadline/focus behavior, required accessibility operation, and recovery administrator login. Record blocked third-party EXE/renamed PE, DLL, scripts, MSI and unapproved packaged app launches. Test reboot/GP refresh, service failure, dependency updates and recovery. Passing the source fixtures or `Test-AppLockerPolicy` rule evaluation does not prove those physical behaviors.
6. Only after review of the actual effective XML, compute its digest with the same installed helper: `. '<protected-install-directory>\cs-policy\cs-policy-functions.ps1'; Get-CsPolicyDigest ([string](Get-AppLockerPolicy -Effective -Xml))`. This helper removes formatting whitespace, orders collections/rules and uses platform XML C14N followed by SHA256; it retains actual rule IDs, names, attributes and conditions. If the digest differs from preparation, review the entire effective difference before accepting it. Never pin an unreviewed policy just to obtain a verified result.
7. Through approved administrative configuration, create the **64-bit** registry key `HKLM\SOFTWARE\NSTU\ComputerScience`. Set `DeploymentMethod` (REG_SZ) to exactly `GroupPolicy`, `PolicyDigest` (REG_SZ) to the reviewed 64 hex digest and `StudentSid` (REG_SZ) to the reviewed individual account SID. Set `PhysicalQualified` (REG_DWORD) to 1 only after the physical allow/block, IME/accessibility and administrator recovery evidence above is independently accepted. Keep it absent or 0 for an unqualified or changed image. Disable inherited ACLs; give SYSTEM and Administrators the required control/read access and ordinary users no write/delete/change-owner/permission rights. SYSTEM, Administrators or TrustedInstaller must own it. The verifier checks these owners and write ACLs at `HKLM`, `SOFTWARE`, `NSTU` and the leaf, including protected inheritance at the leaf. Provision the protected verifier/helper files and their installation-directory ACLs separately.

`DeploymentMethod` and `PhysicalQualified` are protected operator attestations. The GP cmdlet cannot discover or verify CSP/MDM enforcement, and the physical flag cannot independently prove lab evidence. The operator must establish the GPO-only deployment origin and physical qualification before setting either value. Clear physical qualification before an image, dependency or policy change and requalify it.

Keep policy state verification distinct from physical qualification, actual network containment, persistent source/UWF crash recovery, and authenticated physical Linux judge availability. A `policy_verified` result alone must never imply exam safety or enable an otherwise unqualified protected Begin.

## Fixed native probe contract

Separately deploy `cs-policy\verify-cs-policy.ps1` and neighboring `cs-policy\cs-policy-functions.ps1` beneath the service's fixed protected installation directory, adjacent to `nstu-service.exe`. The installer does not package PowerShell payloads. Native code must check these fixed paths, both reviewed script hashes and protected ACLs/reparse-free ancestry. Invoke the fixed **64-bit Windows PowerShell** executable with `-NoProfile -NonInteractive -File <fixed-script-path>` as SYSTEM, supplying no candidate arguments, environment-derived script path, XML, student SID or digest. Bound process duration/output in the native caller. The verifier rejects a 32-bit host and reads only the fixed HKLM configuration, its ACL ancestry, AppIdsvc and `Get-AppLockerPolicy -Effective -Xml`.

It emits one compact JSON line with exactly `version`, `status`, `code`; it never emits XML, account identities, filesystem paths, submitted source or secrets. Exit 0 means `{"version":1,"status":"verified","code":"policy_verified"}`. Exit 1 reports `status="unavailable"` and one of `probe_unavailable`, `configuration_unprotected`, `configuration_invalid`, `deployment_method_invalid`, `physical_not_qualified`, `appid_not_running`, `policy_invalid`, `policy_digest_mismatch`. Missing tools/permissions/configuration fail closed. It requires the explicit physical qualification DWORD, `AppIdsvc` actually Running, exact enforced collections, individually targeted student rules, explicit recovery rules and the reviewed effective digest. A future policy change requires review, a new configured digest and renewed physical qualification.
