# Computer science judge deployment

The source supports a dedicated physical Linux judgehost. No Linux judgehost has been provisioned or qualified by this change. Windows teacher, student agent and SYSTEM service relay source and receipts; they never compile or execute student source. A missing authenticated judge reports unavailable and prevents judged protected Begin. Editor preparation remains usable under its session policy.

## Boundary and fixed version 1 behavior

The teacher's authenticated native proxy is the only broker caller. It verifies the current SAS-authenticated socket, provisioned client and server-issued full exam context before forwarding. Never expose the broker token, private grading store or worker sockets to candidates. Keep the existing 16 KiB answer path separate from 32 KiB programming source.

Candidate packages contain public statements and canonical samples only. Private grading is a separate operator import bound to the same public package digest. Version 1 supports C++20 and Python3, one source file, byte-exact stdout comparison and noninteractive standard input/output. It sends storage receipts only in Exam, Contest and Practice. Finish/Stop/deadline/reconnect never releases results. Public runs show only public input diagnostics, with a combined 24 KiB output cap.

Source limit is 32768 UTF-8 bytes. NUL, DEL and ASCII controls other than TAB/LF/CR are rejected. Sample input/output limit is 4096 UTF-8 bytes each, with 1–8 pairs and at most 64 problems. The complete manifest is at most 128 KiB. Prompt text is at most 8000 UTF-8 bytes; optional instruction/input/output descriptions, constraints and explanation are each at most 4000. Time limits are 100–10000 ms; memory is 16–512 MiB. The first version accepts absent or empty allowedOrigins/documents lists and plaintext offline content. Source and samples are preserved exactly. Draft revisions are positive JavaScript-safe integers up to 9007199254740991. Private cases have separately bounded operator intake; importing public Codeforces metadata does not supply private cases or checker rights.

## Physical Linux prerequisites

Provide a maintained Linux system with cgroup v2, namespaces, Linux >=5.19 peak-memory support and a quota-capable Isolate box filesystem. Reserve separate worker capacity for public and private lanes; disable swap and host collection of submitted-program core dumps. Keep classroom accounts, other workloads, teacher shares, credentials and unrestricted devices off this host.

Install a reviewed **standalone IOI Isolate** build. Record its release/commit, binary SHA256, GPLv2+ license/source notice and `isolate --version` receipt. Its privileged supervisor is allowed only for dedicated worker users; submitted programs run under distinct unprivileged box UIDs. Read the installed release's manual rather than deploying from a floating development branch. Official references: [Isolate manual](https://www.ucw.cz/isolate/isolate.1.html), [Isolate source](https://github.com/ioi/isolate).

Create a read-only root filesystem containing only the pinned C++ compiler, linker, headers/libraries and Python interpreter/standard library. Pin every regular file/symlink target in its deployment manifest. Use fixed `/usr/bin/g++` and `/usr/bin/python3` inside that filesystem; no downloads/package installation during jobs. Bind only its required directories read-only. Public and private boxes/worker state roots/socket paths use separate Unix identities and permissions. Neither worker can read the broker DB, TLS/token files or the other lane's state. No `--share-net`, `--inherit-fds`, `--full-env`, host sockets or arbitrary mounts.

Supply TLS at the operator HTTPS frontend, restrict ingress to the teacher proxy's network identity, and configure its secret in a protected environment/credential file. The Python broker binds loopback only. Use nginx request/body/rate/connection limits and disable access/body logging that would expose student source or credentials. The broker independently checks its bearer credential and strict JSON. Never enable CORS or a candidate-facing verdict endpoint.

Provision credentials and TLS through the institution's approved operations flow. This source change does not generate production keys, alter firewalls/users/services, disable swap, change boot settings or install software. Do not copy example values into production as secrets.

## API for the native teacher proxy

All routes are authenticated `POST` requests with `Content-Type: application/json`, `Authorization: Bearer <protected operator secret>`. JSON rejects duplicate/unknown keys, invalid UTF-8, nonfinite numbers, unsupported version, wrong context and bounds. The five context fields are `packageId`, `packageDigestHex` (64 lowercase hex), `clientIdHex` (32 lowercase hex), `sessionIdHex` (32 lowercase hex), `candidateId`. `programmingVersion` is always 1. Package/problem/sample/request/inventory identifiers begin with `[A-Za-z0-9_]`, continue with `[A-Za-z0-9_.-]` and have at most 96 bytes. Retries preserve their requestId.

| Route | Body | Result |
|---|---|---|
| `/v1/packages` | version, packageId, packageDigestHex, manifest | Immutable validated public registration. Package digest is the operator/native-verified package binding, not an inferred digest of only JSON. |
| `/v1/grading` | version, packageId, packageDigestHex, gradingDigestHex, problems `[{id,revision,cases:[{input,output}]}]` | Separate private registration. Digest is SHA256 of canonical compact sorted-key UTF-8 JSON excluding gradingDigestHex. No executable/custom checker. |
| `/v1/sessions` | full context, version, sessionMode, gradingDigestHex | Durable frozen context; no timer starts yet. |
| `/v1/validate-context` | exactly full flat context and version | Read-only check of a preexisting durable session. Minimal flat context/version/status known/serverTime; unknown returns the same minimal shape with status unknown and HTTP404. Never creates or prepares a session. |
| `/v1/begin` | full context, version, requestId, durationSeconds | Persisted server start/deadline. Root broadcasts these authoritative values; retries never restart the timer. Requires real runner availability. |
| `/v1/stop` | full context, version, requestId | Durable closure; receipt replay and late-source recovery remain possible. No result release. |
| `/v1/programming` | full context, version, requestId, operation and fields below | Allowlisted candidate response only, sent through native authentication. |

`draft`, `submit` and `run` carry `problemId`, `problemRevision`, `language`, `source`, `draftRevision`; run additionally carries canonical `sampleId`. Draft stores per-language revision without grading. Submit commits immutable source/receipt/enqueue in one SQLite transaction. Run uses a source snapshot and does not submit it. `cancel` carries `targetRunId` and the original problem ID/revision/language; it can stop only that context's matching current public run. `recover` carries problem ID/revision/language and returns one sourceBase64 document plus latestReceiptId/receiptDigest/finalized. `finalize` carries receiptIds and noSourceProblemIds covering the whole problem inventory, each list at most 64 items. `ready` has no source fields and returns runnerReady/reason.

Responses have `type=exam_programming_response`, programmingVersion=1, operation/request identity, five flat context fields, serverTime in Unix milliseconds, `status` and safe operation fields. All problem responses bind `problemId`, problemRevision and language; source responses also bind draftRevision/sourceDigest. Stored receipts include stable receiptId/serverTime and `received` or `late`; late/unverified source is retained and never automatically eligible. Recovery uses `recovered`; Finish uses `finalized` with a stable durable receiptId. Cancel returns `cancelled` only after the matching owned run has returned through cleanup, `unavailable` when termination/cleanup fails, or `rejected` for a nonmatching run. Public time limits use `timeout`; public memory/output failures use `runtime_error`. Internal private outcomes remain separate. Public run responses contain safe stdout/stderr/diagnostics, truncation and public sampleMatched only. They never contain private case details, verdicts, grades, progress or queue positions. Recovery returns one document per requested problem/language so 32 KiB sourceBase64 fits one current native frame. Recovery chooses the highest draftRevision across autosaved and received source documents, while latestReceiptId/receiptDigest retain receipt chronology; the candidate must preserve a newer local draft during reconciliation.

HTTP errors are static protocol/admission codes: 401 unauthorized; 400 invalid/unknown/bounds; 404 unknown route/context/problem/sample; 409 immutable-ID/revision/state conflict; 503 runner/storage/queue unavailable. Error details do not include source, test data, system paths, stack traces or credentials. The proxy preserves pending source and displays truthful retry/assistance state.

After a teacher-server restart loses its in-memory issued contexts, the native proxy may validate an old service-owned tuple through `/v1/validate-context`, outside its control locks. It must still bind the current SAS-authenticated socket and provisioned client ID. A candidate-supplied tuple does not establish authority. Unknown tuples remain unavailable and are neither created nor discarded blindly.

For this path the native proxy adds the server-only boolean `recoveryOnly=true` to `/v1/programming`; the browser/native candidate wire never supplies it. This mode permits only draft, submit, finalize and recover. It denies run/cancel/ready and does not begin or reset the timer. Fresh recovered submissions are durably retained as late/ineligible even before the deadline; previously eligible sources and scoring remain intact. The admission flag is excluded from immutable retry hashes, so an existing lost-ACK receipt remains unchanged and a late receipt can never become eligible through replay. Recovered drafts retain their original revision/timer semantics. The validation endpoint and these responses contain no grading data or private worker state.

## Durability and scoring

SQLite stores package/grading/session, drafts, immutable submissions with stable receipts and private enqueue/result state. Its transaction commits before a receipt is returned; crash restart retries private work without changing candidate delivery state. A single broker holds an exclusive database lease. Session preparation freezes the SHA256 of the complete worker configuration, including Isolate/kernel/rootfs pins and lane identities. Both worker readiness reports and every run request must match that full identity, so worker restart between readiness and execution cannot substitute a different runtime. Incompatible pending receipts stay stored while compatible sessions can continue judging. Previously unpinned session databases migrate to recovery/receipt replay until a new context is prepared. The broker captures its trusted clock immediately after reading the complete authenticated HTTP body, before JSON parsing or waiting for storage/readiness locks; this retained timestamp determines submission eligibility. Client-supplied timing fields are forbidden. Separate serialized clock observations prevent reordered processing from creating a false rollback; a real regression blocks new trusted admission until operator clock recovery and broker restart. Closed contexts remain recoverable. Recovery selects the highest draftRevision source document independently of receipt chronology, so delayed older requests do not replace a newer editor document.

Empty source at Finish does not withdraw earlier received submissions. Show that sentence in opening instructions and Finish confirmation. Submission retries keep the original request ID; deliberate new snapshots use a new request ID. The first version limits each session to 1024 immutable submissions and the SQLite database to 524288 pages (normally 2 GiB). Exhaustion rejects new writes and retains stored records; deploy measured capacity/retention before real assessments. It recompiles each private case in a fresh box; calibrate the maximum 64-case private bundle and cohort workload before enabling protected Begin.

There is one public run per candidate, at most eight outstanding broker public runs, sixteen broker request threads and four threads per lane worker. Each worker executes one owned job at a time; busy private capacity returns work to pending without consuming judging retries. Ready/Begin query independent worker readiness handlers and never wait for private verdict computation. Physical capacity and shared-host timing still require qualification.

Exam uses the latest eligible received submission per problem for all-or-nothing published points. Contest uses the first eligible accepted submission, with floor(elapsedMs/60000) plus 20 minutes per preceding wrong answer/runtime/time/memory/output failure; compile/infrastructure errors do not add penalty. Private worker shutdown cancellation follows the bounded infrastructure retry path and never adds a contest penalty. This is NSTU sealed scoring, not official ICPC compliance. Scores stay in the private operator processing layer. No post-session release API is provided in version 1.

The local source store must use the institution-approved persistent Windows data root with service-side durable acknowledgments. Browser storage alone does not prove durability under UWF. Storage exhaustion never truncates source or grants a Saved/Received label. Institution policy must define source/private-evidence retention, restricted export, backup expiry and deletion before a real assessment deployment.

Every symlink resolves within the rootfs; the root itself and every file/directory are root-owned and not group/world writable. State roots are distinct worker-owned mode0700 directories. The adapter rejects special files and does not mount the host's `/dev` or `/etc`. Compilation and execution pass input directly through owned pipes, avoiding host reads/writes through attacker-created box paths.
